# Agent A：地圖與路線規劃介面

本工作以 [共用規格](00-product-and-contract.md) 為準。目標是讓使用者在地圖上選店、調整站序及閱讀路線。此次先交付規格，收到實作任務後才開始寫程式。

## 工作範圍

1. 在已指定的首發平台整合 MapLibre，讀取服務端提供的 style 與 attribution。
2. 地圖顯示目前位置、酒吧、起點、終點、編號站點與分段路線。
3. 提供目前地圖範圍搜尋。「搜尋此區域」由使用者觸發，不隨地圖每次移動持續請求。
4. 搜尋結果同步呈現清單與圖釘，支援載入下一頁。點選任一結果皆能查看詳情並加入站點。
5. 支援長按地圖設定起終點及自訂站點，自訂站點名稱不可為空。
6. 規劃清單支援排序、刪除與停留時間修改；除拖曳外提供上移及下移操作。
7. 顯示各段距離、步行時間、各站停留時間與總計。公尺及秒由 API 提供，客戶端只做顯示換算與四捨五入。
8. 在裝置上儲存、載入與刪除多份 RoutePlan。儲存結果可附帶 RouteResult，但恢復後標示為已儲存的估算。

## 狀態與互動規則

- 建立五分頁 Tab bar，左至右固定為「首頁」、「地圖」、「路跑」、「團體」、「你」，預設顯示首頁。分頁用途依共用規格。
- 地圖與路跑共用目前 RoutePlan。加入酒吧後切換至路跑可立即看到該站，返回地圖仍保留視角、搜尋條件與目前路線。
- 首頁提供開始規劃與恢復草稿入口；團體細部功能待定；你先提供本機設定與資料來源說明。不新增未定義的登入或團體流程。
- 地圖、搜尋及路由使用獨立載入狀態。底圖失敗時仍可編輯已有清單。
- 未具備起點、至少一間酒吧及有效終點設定時，「計算路線」不可用，畫面說明缺少項目。
- 超過八站或重複加入同一 placeId 時，顯示原因且不修改規劃。
- 編輯計畫立即使結果失效。保留舊折線時須降淡並顯示需重新計算。
- 發出計算時記錄規劃版本與 clientRequestId。只有兩者仍符合目前畫面才能套用結果，編輯或離開畫面時取消不再需要的請求。
- 定位只在使用者選擇「使用目前位置」後請求前景權限。拒絕或定位逾時時提供地圖選點。
- 搜尋沒有地址或營業時間時顯示「未提供」，不推算營業中。
- 顯示 NO_WALKABLE_ROUTE 時標示問題站點，提供移動站點、刪除或重試的操作。
- 草稿損壞或 schemaVersion 不支援時顯示載入失敗，不靜默覆寫原資料。

## 邊界與交付物

客戶端只透過共用 HTTP API 取得地點與路由。不得把酒吧資料匯入、步行路由演算法或供應商金鑰寫進 UI。裝置定位封裝在平台介面內，地理資料保存為共用 Coordinate。

Agent A 交付可執行客戶端、API adapter、依共用範例運作的 mock、操作說明與驗收記錄。修改範圍為客戶端目錄、客戶端測試與其說明；不自行變更服務端 API。

## 驗收案例

- 五個分頁標籤及左右順序符合規格，地圖選站後切到路跑再返回，規劃內容與地圖視角皆保留。
- 不給定位權限，仍可手動完成起點、三間酒吧、終點及路線預覽。
- 將第二站移至第一站，重新計算後編號、清單與折線順序一致。
- 回到起點與自訂終點切換後，正確更新規劃並使舊結果失效。
- 計算 A 尚未完成時修改站點並計算 B。A 最後抵達仍不得覆蓋 B。
- 關閉並重開應用程式後可恢復已儲存草稿及停留時間。
- 搜尋空結果、路由 422、503、504、底圖失敗均有可理解的畫面與恢復方式。
- 小尺寸手機畫面可完成所有操作，清單與提示不遮住必要按鈕及授權標示。

整合前可用 mock 驗證操作，交付時須另外記錄至少一次真實 API 完整流程。
